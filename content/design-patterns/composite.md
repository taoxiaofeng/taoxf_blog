# 组合模式（Composite）

**别名：** 对象树（Object Tree）

## 意图

**组合模式**是一种结构型设计模式，你可以使用它将对象组合成树状结构以表示"部分-整体"的层次结构。组合能让客户端以一致的方式处理个别对象以及对象组合。

## 问题

如果应用的核心模型能用树状结构表示，在应用中使用组合模式才有价值。

例如，你有两类对象：`产品` 和 `盒子`。一个 `盒子` 中可以包含多个 `产品` 或几个较小的 `盒子`。这些小 `盒子` 中同样可以包含一些 `产品` 或更小的 `盒子`，以此类推。

假设你希望在这些类的基础上开发一个订购系统。订单中可以包含无包装的简单产品，也可以包含装满产品的盒子……以及其他盒子。你如何计算每个订单的总价格？

你可以尝试直接计算：打开所有盒子，找到每件产品然后计算总价。这在现实世界中还可行，但在程序中并非简单地循环遍历就能完成。你必须事先知道所有 `产品` 和 `盒子` 的类别，所有盒子的嵌套层数以及其他繁琐的细节，这使得直接计算变得极其笨拙甚至不可行。

## 解决方案

组合模式建议使用一个通用接口来与 `产品` 和 `盒子` 进行交互，并且在该接口中声明一个计算总价的方法。

那么方法该如何设计呢？对于一个产品，该方法直接返回其价格；对于一个盒子，该方法遍历盒子中的所有项目，询问每个项目的价格，然后返回该盒子的总价格。如果其中某个项目是小一号的盒子，该盒子也会遍历其中的内容，以此类推，直到所有内部组件的价格都计算完毕。一个盒子甚至可以在最终价格上增加额外费用作为打包成本。

该方式最大的优点在于你无需了解构成树状结构的对象的具体类。你不需要知道对象是简单的产品还是复杂的盒子。你只需通过通用接口调用方法即可。当你调用该方法后，对象会将请求沿着树结构向下传递。

## 结构

1. **组件（Component）** 接口描述了树中简单项目和复杂项目所共有的操作。
2. **叶节点（Leaf）** 是树的基本结构，它不包含子项目。一般情况下叶节点最终会完成大部分的实际工作，因为它们没有可以委派工作的子对象。
3. **容器（Composite）**——又名"组合"——是包含叶节点或其他容器等子项目的单位。容器不知道其子项目所属的具体类，它只通过通用的组件接口与其子项目交互。容器接收到请求后会将工作分配给其子项目，处理中间结果，然后将最终结果返回给客户端。
4. **客户端（Client）** 通过组件接口与所有项目交互。因此客户端能以相同方式与树状结构中的简单或复杂项目交互。

## 伪代码

```
// 组件接口会声明组合中简单和复杂对象的通用操作。
interface Graphic is
    method move(x, y)
    method draw()

// 叶节点代表组合的终端对象。叶节点对象无法包含任何子对象。
// 叶节点对象通常会完成实际的工作，组合对象则仅会将工作
// 委派给自己的子部件。
class Dot implements Graphic is
    field x, y

    constructor Dot(x, y) { ... }

    method move(x, y) is
        this.x += x, this.y += y

    method draw() is
        // 在坐标 (X,Y) 处绘制一个点。

// 所有组件类都可以扩展其他组件。
class Circle extends Dot is
    field radius

    constructor Circle(x, y, radius) { ... }

    method draw() is
        // 在坐标 (X,Y) 处绘制一个半径为 R 的圆。

// 组合类表示可能包含子项目的复杂组件。组合对象通常会
// 将实际工作委派给子项目，然后"汇总"结果。
class CompoundGraphic implements Graphic is
    field children: array of Graphic

    method add(child: Graphic) is
        // 添加一个子项目到子项目列表中。

    method remove(child: Graphic) is
        // 从子项目列表中移除一个子项目。

    method move(x, y) is
        foreach (child in children) do
            child.move(x, y)

    method draw() is
        // 1. 对所有子组件绘制一个虚线矩形作为边界。
        // 2. 遍历所有子项目并执行其 draw 方法。

// 客户端代码通过基础接口与所有组件进行交互。
// 这样客户端代码就可以同时支持简单的叶节点组件
// 和复杂的组合组件。
class ImageEditor is
    field all: CompoundGraphic

    method load() is
        all = new CompoundGraphic()
        all.add(new Dot(1, 2))
        all.add(new Circle(5, 3, 10))
        // ...

    // 将选中的组件组合成一个复杂的组合组件。
    method groupSelected(components: array of Graphic) is
        group = new CompoundGraphic()
        foreach (component in components) do
            group.add(component)
            all.remove(component)
        all.add(group)
        // 所有组件都将被绘制。
        all.draw()
```

## 适用场景

- 如果你需要实现树状对象结构，可以使用组合模式。组合模式为你提供了两种共享公共接口的基本元素类型：简单叶节点和复杂容器。容器中可以包含叶节点和其他容器。这使得你可以构建类似递归嵌套的树状对象结构。
- 如果你希望客户端代码以相同方式处理简单和复杂元素，可以使用该模式。组合模式中定义的所有元素共享同一个接口。在这一接口的帮助下，客户端不必在意其所使用的对象的具体类。

## 实现步骤

1. 确保你的应用的核心模型能用树状结构表示。尝试将其分解为简单元素和容器。记住，容器必须能够同时包含简单元素和其他容器。
2. 声明组件接口及其一组方法，这些方法对简单和复杂元素都有意义。
3. 创建一个叶节点类表示简单元素。程序中可以有多个不同的叶节点类。
4. 创建一个容器类表示复杂元素。在该类中创建一个数组成员变量来存储对于其子元素的引用。该数组必须能够同时保存叶节点和容器，因此请确保将其声明为组件接口类型。实现组件接口方法时，记住容器应将大部分工作委派给其子元素。
5. 最后在容器中定义添加和删除子元素的方法。

## 优缺点

### 优点

- 你可以利用多态和递归机制更方便地使用复杂树结构。
- **开闭原则。** 无需更改现有代码，你就可以在应用中添加新元素，使其成为对象树的一部分。

### 缺点

- 对于功能差异较大的类，提供公共接口或许会有困难。在特定情况下你需要过度一般化组件接口，使其变得令人难以理解。

## 与其他模式的关系

- 你可以在创建复杂**组合**树时使用**建造者模式**，因为这可以让其构造步骤以递归的方式运行。
- **责任链模式**通常和**组合模式**结合使用。在这种情况下，叶组件接收到请求后可以将请求沿包含全体父组件的链一直传递到对象树的底部。
- 你可以使用**迭代器模式**来遍历**组合**树。
- 你可以使用**访问者模式**对整个**组合**树执行操作。
- 你可以使用**享元模式**实现**组合**树的共享叶节点以节省内存。
- **组合**和**装饰器模式**的结构图很相似，因为两者都依赖递归组合来组织无限数量的对象。装饰器类似于组合，但其只有一个子组件。此外还有一个明显的不同：装饰器为被封装对象添加了额外的职责，组合仅对其子节点的结果进行了"汇总"。但模式也可以相互合作：你可以使用装饰器来扩展组合树中特定对象的行为。
