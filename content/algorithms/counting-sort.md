## 概述

计数排序（Counting Sort）是一种**非比较排序**算法，它不通过比较元素的大小来确定顺序，而是通过统计每个元素出现的次数来确定元素在排序后数组中的位置。

计数排序的时间复杂度为 O(n + k)，其中 n 是数组长度，k 是数据范围（最大值与最小值之差）。当 k 不太大时（即数据范围有限），计数排序的效率远高于任何比较排序算法。

计数排序是稳定排序，常被用作基数排序的子过程。

## 算法原理

计数排序的工作方式如下：

### 基本思想
1. 找出数组中的最大值和最小值，确定数据范围 k
2. 创建一个长度为 k+1 的计数数组 count
3. 遍历原数组，统计每个元素出现的次数
4. 对计数数组做前缀和（累加），得到每个元素在排序后数组中的最终位置
5. 从后往前遍历原数组，将每个元素放到正确的位置（保证稳定性）

### 为什么从后往前遍历
从后往前遍历原数组可以保证排序的稳定性。对于相同值的元素，后出现的会被放在更后面的位置，从而保持了原始顺序。

### 前提条件
- 元素必须是整数（或可以映射为整数）
- 数据范围 k 不能太大，否则空间开销过大

## 执行步骤

以数组 `[64, 34, 25, 12, 22, 11, 90]` 为例（为了演示更清晰，使用简化版本）：

为了更清晰地展示，我们使用较小范围的数组 `[4, 2, 2, 8, 3, 3, 1]`：

**步骤 1：找出范围**
- 最小值 min = 1，最大值 max = 8
- 范围 k = 8 - 1 + 1 = 8

**步骤 2：统计频次**
- count[1]=1, count[2]=2, count[3]=2, count[4]=1, count[8]=1
- count 数组：[0, 1, 2, 2, 1, 0, 0, 0, 1]（索引 0-8）

**步骤 3：计算前缀和（累积计数）**
- count[0]=0, count[1]=1, count[2]=3, count[3]=5, count[4]=6, count[5]=6, count[6]=6, count[7]=6, count[8]=7

前缀和的含义：count[i] 表示值 ≤ i 的元素个数，即值为 i 的元素在排序结果中的最后位置。

**步骤 4：从后往前遍历原数组，放置元素**
- arr[6]=1 → count[1]=1 → 放在位置 0 → count[1]-- → result=[1,_,_,_,_,_,_]
- arr[5]=3 → count[3]=5 → 放在位置 4 → count[3]-- → result=[1,_,_,_,3,_,_]
- arr[4]=3 → count[3]=4 → 放在位置 3 → count[3]-- → result=[1,_,_,3,3,_,_]
- arr[3]=8 → count[8]=7 → 放在位置 6 → count[8]-- → result=[1,_,_,3,3,_,8]
- arr[2]=2 → count[2]=3 → 放在位置 2 → count[2]-- → result=[1,_,2,3,3,_,8]
- arr[1]=2 → count[2]=2 → 放在位置 1 → count[2]-- → result=[1,2,2,3,3,_,8]
- arr[0]=4 → count[4]=6 → 放在位置 5 → count[4]-- → result=[1,2,2,3,3,4,8]

**最终结果：[1, 2, 2, 3, 3, 4, 8]**

## 代码实现

```java
public class CountingSort {

    /**
     * 计数排序（稳定版本）
     */
    public static int[] countingSort(int[] arr) {
        if (arr.length == 0) return arr;

        // 找出最大值和最小值
        int max = arr[0], min = arr[0];
        for (int num : arr) {
            max = Math.max(max, num);
            min = Math.min(min, num);
        }

        // 创建计数数组
        int range = max - min + 1;
        int[] count = new int[range];
        int[] output = new int[arr.length];

        // 统计每个元素出现的次数
        for (int num : arr) {
            count[num - min]++;
        }

        // 计算前缀和
        for (int i = 1; i < range; i++) {
            count[i] += count[i - 1];
        }

        // 从后往前遍历原数组，保证稳定性
        for (int i = arr.length - 1; i >= 0; i--) {
            output[count[arr[i] - min] - 1] = arr[i];
            count[arr[i] - min]--;
        }

        return output;
    }

    public static void main(String[] args) {
        int[] arr = {64, 34, 25, 12, 22, 11, 90};
        int[] sorted = countingSort(arr);
        System.out.println(java.util.Arrays.toString(sorted));
        // 输出: [11, 12, 22, 25, 34, 64, 90]
    }
}
```

```python
def counting_sort(arr):
    """计数排序（稳定版本）"""
    if not arr:
        return arr

    # 找出最大值和最小值
    max_val = max(arr)
    min_val = min(arr)

    # 创建计数数组
    range_val = max_val - min_val + 1
    count = [0] * range_val
    output = [0] * len(arr)

    # 统计每个元素出现的次数
    for num in arr:
        count[num - min_val] += 1

    # 计算前缀和
    for i in range(1, range_val):
        count[i] += count[i - 1]

    # 从后往前遍历原数组，保证稳定性
    for i in range(len(arr) - 1, -1, -1):
        output[count[arr[i] - min_val] - 1] = arr[i]
        count[arr[i] - min_val] -= 1

    return output


# 示例
arr = [64, 34, 25, 12, 22, 11, 90]
print(counting_sort(arr))
# 输出: [11, 12, 22, 25, 34, 64, 90]
```

## 复杂度分析

| 复杂度类型 | 复杂度 | 说明 |
|-----------|--------|------|
| 最好时间复杂度 | O(n + k) | k 为数据范围（max - min + 1） |
| 最坏时间复杂度 | O(n + k) | 所有情况下都相同 |
| 平均时间复杂度 | O(n + k) | 所有情况下都相同 |
| 空间复杂度 | O(n + k) | 需要计数数组 O(k) 和输出数组 O(n) |

**时间复杂度分析**：
- 统计频次：O(n)
- 计算前缀和：O(k)
- 放置元素：O(n)
- 总计：O(n + k)

**当 k = O(n) 时**，计数排序的时间复杂度为 O(n)，是线性时间排序。

**当 k >> n 时**（如 k = n²），计数排序退化为 O(n²)，此时不如比较排序。

## 稳定性分析

计数排序是**稳定排序**。

稳定性的关键在于最后一步"从后往前遍历原数组"：
- 对于相同值的元素，后出现的（索引大的）先被处理
- 先被处理的元素放在更靠后的位置（count 值更大）
- 因此，相同值的元素在排序后保持原来的相对顺序

如果改为从前往后遍历，排序结果仍然正确，但稳定性会被破坏。

## 适用场景

计数排序适合在以下场景中使用：

- **数据范围有限**：当 k（数据范围）与 n（数据量）相近或 k < n 时，效率极高
- **整数排序**：元素是整数或可以映射为整数
- **需要线性时间排序**：当 k = O(n) 时，计数排序是 O(n) 的
- **作为基数排序的子程序**：基数排序的每一位排序通常使用计数排序
- **统计类问题**：需要知道每个值出现次数的场景

**不适合的场景**：
- 数据范围很大（如浮点数、字符串）
- 数据是浮点数（无法直接使用）
- k >> n 时空间和时间开销过大

## 与其他排序算法的比较

| 算法 | 平均时间复杂度 | 空间复杂度 | 稳定性 | 排序方式 |
|------|--------------|-----------|--------|---------|
| 计数排序 | O(n + k) | O(n + k) | 稳定 | 非比较 |
| 基数排序 | O(d*(n+k)) | O(n + k) | 稳定 | 非比较 |
| 桶排序 | O(n + k) | O(n + k) | 稳定 | 非比较 |
| 快速排序 | O(n log n) | O(log n) | 不稳定 | 比较 |
| 归并排序 | O(n log n) | O(n) | 稳定 | 比较 |

**与比较排序比较**：比较排序的理论下界是 O(n log n)，而计数排序可以达到 O(n + k)。这是因为计数排序利用了元素值本身的信息（而非仅通过比较获取信息）。

**与基数排序比较**：计数排序处理单个"数位"，而基数排序将计数排序作为子程序处理多个数位。基数排序可以处理更大范围的数据。

**与桶排序比较**：计数排序可以看作桶排序的特殊情况，每个桶对应一个值。桶排序更通用，可以处理浮点数。

**总结**：计数排序在数据范围有限的整数排序场景中是最优选择，可以达到线性时间复杂度，但需要额外的 O(n + k) 空间，且仅适用于整数数据。
