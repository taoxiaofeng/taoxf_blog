## 概述

选择排序（Selection Sort）是一种简单直观的排序算法。它的工作原理是：每次从未排序的部分中找到最小（或最大）的元素，将其放到已排序部分的末尾。

选择排序的主要特点是：无论输入数据的初始状态如何，其时间复杂度始终为 O(n²)，但它的优势在于交换次数最少——每轮只需进行一次交换，这在交换成本较高的场景下具有优势。

## 算法原理

选择排序的工作方式如下：

1. 在未排序序列中找到最小元素，存放到排序序列的起始位置
2. 从剩余未排序元素中继续寻找最小元素，放到已排序序列的末尾
3. 重复步骤 2，直到所有元素均排序完毕

整个过程将数组分为两个部分：
- **左侧已排序部分**：从左到右逐渐增长
- **右侧未排序部分**：从左到右逐渐缩小

每一轮从未排序部分选出最小值，与未排序部分的第一个元素交换位置。

## 执行步骤

以数组 `[64, 34, 25, 12, 22, 11, 90]` 为例，展示选择排序的执行过程：

**第一轮（i=0）：**
- 在 [64, 34, 25, 12, 22, 11, 90] 中找最小值
- 最小值为 11（索引 5）
- 将 11 与位置 0 的 64 交换
- 结果：[**11**, 34, 25, 12, 22, 64, 90]

**第二轮（i=1）：**
- 在 [34, 25, 12, 22, 64, 90] 中找最小值
- 最小值为 12（索引 3）
- 将 12 与位置 1 的 34 交换
- 结果：[11, **12**, 25, 34, 22, 64, 90]

**第三轮（i=2）：**
- 在 [25, 34, 22, 64, 90] 中找最小值
- 最小值为 22（索引 4）
- 将 22 与位置 2 的 25 交换
- 结果：[11, 12, **22**, 34, 25, 64, 90]

**第四轮（i=3）：**
- 在 [34, 25, 64, 90] 中找最小值
- 最小值为 25（索引 4）
- 将 25 与位置 3 的 34 交换
- 结果：[11, 12, 22, **25**, 34, 64, 90]

**第五轮（i=4）：**
- 在 [34, 64, 90] 中找最小值
- 最小值为 34（索引 4），已在正确位置
- 结果：[11, 12, 22, 25, **34**, 64, 90]

**第六轮（i=5）：**
- 在 [64, 90] 中找最小值
- 最小值为 64（索引 5），已在正确位置
- 结果：[11, 12, 22, 25, 34, **64**, 90]

**最终结果：[11, 12, 22, 25, 34, 64, 90]**

## 代码实现

```java
public class SelectionSort {

    /**
     * 选择排序
     */
    public static void selectionSort(int[] arr) {
        int n = arr.length;
        for (int i = 0; i < n - 1; i++) {
            // 找到未排序部分的最小元素索引
            int minIndex = i;
            for (int j = i + 1; j < n; j++) {
                if (arr[j] < arr[minIndex]) {
                    minIndex = j;
                }
            }
            // 将最小元素与未排序部分的第一个元素交换
            if (minIndex != i) {
                int temp = arr[i];
                arr[i] = arr[minIndex];
                arr[minIndex] = temp;
            }
        }
    }

    public static void main(String[] args) {
        int[] arr = {64, 34, 25, 12, 22, 11, 90};
        selectionSort(arr);
        System.out.println(java.util.Arrays.toString(arr));
        // 输出: [11, 12, 22, 25, 34, 64, 90]
    }
}
```

```python
def selection_sort(arr):
    """选择排序"""
    n = len(arr)
    for i in range(n - 1):
        # 找到未排序部分的最小元素索引
        min_index = i
        for j in range(i + 1, n):
            if arr[j] < arr[min_index]:
                min_index = j
        # 将最小元素与未排序部分的第一个元素交换
        if min_index != i:
            arr[i], arr[min_index] = arr[min_index], arr[i]
    return arr


# 示例
arr = [64, 34, 25, 12, 22, 11, 90]
print(selection_sort(arr))
# 输出: [11, 12, 22, 25, 34, 64, 90]
```

## 复杂度分析

| 复杂度类型 | 复杂度 | 说明 |
|-----------|--------|------|
| 最好时间复杂度 | O(n²) | 即使数组有序，仍需遍历查找最小值 |
| 最坏时间复杂度 | O(n²) | 数组完全逆序 |
| 平均时间复杂度 | O(n²) | 随机排列的数组 |
| 空间复杂度 | O(1) | 只需要常数级别的额外空间 |

**比较次数**：无论数据初始状态如何，比较次数总是 n(n-1)/2 次。

**交换次数**：最多 n-1 次交换（每轮最多一次），这是选择排序的一大优势。

## 稳定性分析

选择排序是**不稳定排序**。

原因在于选择排序在交换时可能改变相同元素的相对顺序。例如：

数组 `[5a, 3, 5b, 2, 1]`：
- 第一轮找到最小值 1（索引 4），与 5a（索引 0）交换
- 结果：`[1, 3, 5b, 2, 5a]`
- 此时 5b 在 5a 之前，相对顺序已被改变

因此，选择排序无法保证相同值元素的相对位置不变。

## 适用场景

选择排序适合在以下场景中使用：

- **交换成本高**：当数据交换的代价远大于比较的代价时（如大型记录），选择排序的优势明显，因为它的交换次数最少
- **数据量较小**：当 n 较小时，O(n²) 的影响不大
- **对内存要求严格**：只需 O(1) 额外空间
- **不要求稳定性**：如果不关心相同元素的相对顺序
- **教学用途**：算法思想简单，适合教学

## 与其他排序算法的比较

| 算法 | 平均时间复杂度 | 最坏时间复杂度 | 空间复杂度 | 稳定性 | 交换次数 |
|------|--------------|--------------|-----------|--------|---------|
| 选择排序 | O(n²) | O(n²) | O(1) | 不稳定 | O(n) |
| 冒泡排序 | O(n²) | O(n²) | O(1) | 稳定 | O(n²) |
| 插入排序 | O(n²) | O(n²) | O(1) | 稳定 | O(n²) |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 | — |
| 快速排序 | O(n log n) | O(n²) | O(log n) | 不稳定 | O(n log n) |

**与冒泡排序比较**：选择排序交换次数远少于冒泡排序（O(n) vs O(n²)），但冒泡排序是稳定的且可以在数据有序时提前终止。

**与插入排序比较**：插入排序在数据基本有序时性能远优于选择排序。但选择排序在交换成本高的场景下更优，因为每轮只做一次交换。

**总结**：选择排序的唯一优势在于交换次数少，适合交换开销大的场景。在一般情况下，插入排序是比选择排序更好的 O(n²) 级别算法。
